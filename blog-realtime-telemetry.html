50,000+ Sensor Records at 60 FPS
[SYSTEM_ARCHITECTURE_BRIEF]

Monitoring critical government physical infrastructure (such as nationwide oil and gas pipelines) requires processing high-velocity sensor telemetry feeds without UI starvation or garbage collection freezes. This article explores how we architected a high-throughput WebSocket ingestion queue, combined with WebGL/HTML5 Canvas batching, to render 50,000+ live data points at a rock-solid 60 FPS.

1. Why Standard DOM Grids Choke at Scale

In typical web dashboards, developers render incoming data points as React components attached to the standard DOM tree. However, when 500+ WebSocket messages arrive per second across 50,000 sensor nodes, the browser spends 95% of its main thread time calculating CSS style recalculations, reflows, and layout geometry.

The result is browser frame dropping down to 10–15 FPS, unbounded memory consumption, and delayed safety anomaly alerts.

2. Web Worker Ingestion & Backpressure Management

To prevent main-thread freezing, all WebSocket connection handling, binary payload unpacking (using Protocol Buffers / ArrayBuffers), and mathematical anomaly detection algorithms were offloaded to a dedicated Web Worker thread:

telemetryWorker.ts (Off-Thread Ingestion) Dedicated Worker 
// Worker Thread: Ingestion, Rolling Window Buffer, Anomaly Filter
let telemetryBuffer: Float32Array = new Float32Array(50000 * 4); // [lat, lng, pressure, temp]

const ws = new WebSocket('wss://telemetry.safety.infra.gov/stream');
ws.binaryType = 'arraybuffer';

ws.onmessage = (event: MessageEvent<ArrayBuffer>) => {
  const incomingData = new Float32Array(event.data);
  
  // Fast memory copy into rolling buffer
  telemetryBuffer.set(incomingData);

  // Perform threshold analysis on worker thread
  const anomalies = detectPressureSpikes(telemetryBuffer);
  
  if (anomalies.length > 0) {
    postMessage({ type: 'ANOMALY_TRIGGER', payload: anomalies });
  }
};

// Batch dispatch to UI thread synchronized with 60 FPS ticker
setInterval(() => {
  // Transfer array buffer without cloning
  const bufferCopy = telemetryBuffer.slice();
  postMessage({ type: 'BATCH_FRAME', buffer: bufferCopy }, [bufferCopy.buffer]);
}, 16.67); // 60 Hz rate

3. Hardware-Accelerated Rendering with WebGL & Instanced Meshes

Instead of rendering thousands of SVG or DOM circle markers on geospatial maps, we leveraged WebGL Instanced Rendering. A single draw call (gl.drawArraysInstanced) transmits the entire 50,000-sensor coordinate matrix directly to the GPU:

sensorShader.vert (Instanced Vertex Shader) GLSL 
#version 300 es
layout (location = 0) in vec2 a_quad_pos;
layout (location = 1) in vec2 a_sensor_coord;
layout (location = 2) in float a_pressure_metric;

uniform mat4 u_projection_matrix;
out float v_pressure;

void main() {
  v_pressure = a_pressure_metric;
  
  // Compute point position dynamically on GPU
  vec2 world_pos = a_sensor_coord + (a_quad_pos * 4.0);
  gl_Position = u_projection_matrix * vec4(world_pos, 0.0, 1.0);
}

5. Summary

Building ultra-high-throughput real-time dashboards requires stepping outside standard DOM paradigms. By combining dedicated worker threads for ingestion, TypedArray zero-copy buffers, and WebGL instancing, browser applications can render complex industrial telemetry with zero lag and instant safety response.
